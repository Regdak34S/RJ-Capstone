# CR-001 — Mobile / responsive redesign

**Requested by:** Demo attendee (Week 10)  
**Date opened:** 2026-11-10  
**Decider:** Reggie Johnson  
**Date decided:** 2026-11-12  

## Request

Ship a mobile-first responsive layout so the tool is usable on a phone browser.

## Three-line impact analysis

1. **Cost:** ~12–16 h (layout, touch targets, re-test acceptance paths, screenshots).  
2. **Blast radius:** All UI surfaces; risk of regressing desktop demo script and accessibility of forms.  
3. **Risk both ways:** Accept → slips FR-ASM-05 / checklist; Reject → mobile users stay on desktop-sized UI (usable but awkward).

## Disposition

**REJECT**

**Reason:** Remaining semester capacity is reserved for Must gaps (assemble, checklist, NAV force) and release hardening. Mobile is Could-level polish relative to Must FRs still open.

**Communication (actual sentence):**  
“I’m not taking a full mobile redesign into this release candidate — it is about two full workdays and would push Must-have assemble/checklist. I’ll keep the layout usable in a phone browser as-is and park a responsive pass on the backlog if capacity appears after RC.”
